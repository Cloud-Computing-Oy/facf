# Security Policy

FACF is in a design and pre-production stage. No repository artifact should currently be treated as an audited production security boundary.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability reporting for this repository when available, or contact a verified Cloud Computing Oy representative through the organization's official channels and request a private security channel.

Include the affected component or document version, impact, reproduction conditions, and any suggested mitigation. Do not send real customer data, production credentials, or destructive proof-of-concept traffic.

## Response principles

Maintainers will acknowledge valid private reports, assess severity and affected versions, coordinate a fix and disclosure where appropriate, and credit reporters who wish to be named. Timelines depend on severity and reproducibility; this file does not promise a commercial SLA.

## Supported versions

There are no production-supported software releases yet. Once releases begin, this section will identify supported versions and security-update policy.
