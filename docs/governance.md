# Governance

FACF separates governance of the open technical project from operation of a commercial network.

## Open project governance

Cloud Computing Oy is the initial project steward and repository owner. Changes are proposed through issues and pull requests, reviewed against documented architecture and security principles, and recorded through architecture decision records when they affect compatibility or trust.

Maintainers may reject changes that weaken security boundaries, create hidden operator lock-in, misrepresent capabilities, or make the protocol dependent on a specific settlement system.

## Managed-network governance

The official managed FACF network is a service operated by Cloud Computing Oy under separate participation terms. The company controls enrollment, verified-provider status, managed-network policies, pricing, SLAs, billing, and incident response. Compatibility with the open protocol does not grant access to that network or the right to represent a service as official.

## Compatibility

Protocol evolution uses explicit versions, deprecation periods, and interoperability tests. Where practical, the reference implementation should remain useful with independent operators.

## Maintainer expansion

New maintainers earn scoped authority through sustained, reviewable contributions and responsible security conduct. Repository administration, release signing, trademarks, commercial contracts, and production-network credentials remain separately controlled.

## Conflicts of interest

Maintainers disclose material interests related to a proposal. Commercial sponsorship is welcome when it is visible and does not override technical review or security requirements.
